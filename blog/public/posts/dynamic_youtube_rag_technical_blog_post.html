The Core Dilemma: Static vs Dynamic Video RAG

Retrieval-Augmented Generation has revolutionized interactions with PDFs, wikis, and markdown libraries. However, adapting this architecture to video content has traditionally suffered from a fatal architectural flaw: treating temporal streams as static flat documents.

❌ The Traditional Video RAG Flaw

Downloads full video or audio streams (often 50–200 MB), transcribes via Whisper end-to-end (taking 2–5 minutes), breaks text into token-based windows, and strips timestamps.

Result: Returns a static wall of transcript. The user is still forced to guess where in a 90-minute video the topic actually took place.

✅ Dynamic YouTube RAG Paradigm

Inspects YouTube’s native caption tracks in ~1.5s via raw json3 / VTT structures. Preserves continuous start/end boundaries on every segment chunk.

Result: Instant query resolution linked directly to clickable player seeking points (e.g., &t=724s) with zero hallucination.

Consider an algorithmic query: "Where is memoization vs tabulation explained?". In traditional document RAG, the LLM outputs a three-paragraph explanation of memoization. In Dynamic YouTube RAG, the system responds with exact temporal navigation chips: 

Question: "Where is memoization vs tabulation explained?"

→ Found: DP Lecture 3 — Memoization Deep Dive @ 12:04  [▶ Seek to 12:04]
→ Found: DP Lecture 5 — Tabulation Recipe      @ 04:31  [▶ Seek to 04:31]

System Architecture: The End-to-End Ingestion Engine

The core pipeline is decoupled into a dual-path transcription layer, a time-window sliding chunker, a dense vector embedder with an in-memory/disk compressed index (vectors.npz or Qdrant), and a dual LLM inference router (Groq & Gemini).

Deep Technical Implementation

1. Sub-Second Native Transcription vs Batched Whisper Fallback

Downloading an audio stream using yt-dlp and transcoding it through FFmpeg introduces an unrecoverable 8–20 second overhead on standard cloud instances. Dynamic YouTube RAG circumvents this entirely by prioritizing the extraction of automated or manual YouTube subtitle payloads. Using json3 extraction, raw timestamp sequences are retrieved in under 1.8 seconds. 

# ytrag/transcribe.py — Fast JSON3 caption extraction
import json
import yt_dlp
from typing import List, Dict

def fetch_subtitles_fast(video_url: str) -> List[Dict]:
    ydl_opts = {
        "skip_download": True,
        "writesubtitles": True,
        "writeautomaticsub": True,
        "subtitlesformat": "json3",
        "quiet": True
    }
    with yt_dlp.YoutubeDL(ydl_opts) as ydl:
        info = ydl.extract_info(video_url, download=False)
        subtitles = info.get("subtitles") or info.get("automatic_captions")
        if subtitles:
            # Parse events to extract word chunks and microsecond timestamps
            return parse_json3_events(subtitles)
            
    # Fallback: Trigger Faster-Whisper on extracted 16kHz audio stream
    return fallback_faster_whisper(video_url)

2. Timestamp-Preserving Time-Window Chunking

Token-based splitters (like recursive character text splitters) drop time metadata or produce arbitrary cuts right in the middle of a spoken sentence. Our engine implements a Temporal Window Sliding Chunker. It enforces a target window (e.g., 60 seconds) with an overlap buffer (e.g., 15 seconds), while rigidly tracking both continuous boundaries:

3. Multilingual Dense Embeddings: BAAI/bge-m3

Real-world educational videos often mix languages (e.g., instructors interweaving English terms with Hindi, Nepali, or regional vernacular). Standard English-only encoders (like standard MiniLM) fail on code-switched queries. We integrated BAAI/bge-m3, a 1024-dimensional model designed specifically for multilingual semantic density and long-context alignment.
