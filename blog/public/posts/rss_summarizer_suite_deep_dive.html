The Information Overload Bottleneck

Engineering and intelligence teams track hundreds of news wires, developer release streams, and RSS feeds every day. The traditional approaches suffer from two polar failure modes:

  • Superficial RSS parsing: Native feed titles and standard RSS descriptions rarely contain the full text or core context, often clipping articles at arbitrary character boundaries.
  • Unbounded scraping overhead: Scraping full web pages introduces noisy DOM trees, scripts, navigations, sidebars, and trackers, which blow up the token count of Large Language Model (LLM) contexts and trigger massive API costs.

To solve this, we architected the RSS & URL Summarizer Suite: an enterprise pipeline combining targeted web extraction (via newspaper3k and feedparser), deterministic NLP tokenization (via nltk), structured GPT-3.5 prompt synthesis, and a unified dual-surface architecture running both FastAPI and Streamlit within a single optimized Docker container.

Deep Dive: The Extraction & Summarization Mechanics

The ingestion pipeline delegates scraping logic to newspaper3k, wrapping raw HTTP connections inside resilient user-agent rotations and fallback HTML entity cleanups. When feeding an arbitrary URL into standard LLM prompts, raw HTML content often triggers context length errors and inflates costs.

The system solves this via a two-stage parsing technique:

  1. Heuristic Main Body Extraction: Stripping navigation bars, ad banners, and boilerplate cookie footers using DOM tree density algorithms.
  2. NLTK Token Separation: Utilizing punkt_tab to evaluate boundary conditions and tokenize sentences, preserving structural cohesiveness before generating LLM prompts.
rss_parser/parser.py Python 
from newspaper import Article
import feedparser
from openai import OpenAI
import os

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

def extract_article_content(url: str) -> dict:
    """Fetches, parses, and strips non-content DOM boilerplate."""
    article = Article(url)
    article.download()
    article.parse()
    article.nlp()  # NLTK punkt extraction
    return {
        "title": article.title,
        "authors": article.authors,
        "publish_date": str(article.publish_date),
        "text": article.text
    }

def generate_llm_summary(text: str) -> str:
    """Executes deterministic few-shot synthesis with OpenAI GPT-3.5."""
    system_prompt = (
        "You are an expert technical editor. Given article text, output: "
        "1. TL;DR (1-2 sentences)\n"
        "2. Key Takeaways (3-5 concise bullets)\n"
        "3. Three relevant hashtags."
    )
    response = client.chat.completions.create(
        model="gpt-3.5-turbo",
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": text[:4000]}  # Enforce token safety window
        ],
        temperature=0.3
    )
    return response.choices[0].message.content

High-Throughput Batching & URL Deduplication

When processing hundreds of links via CSV uploads, duplicate entries across web feeds waste LLM quota. The Streamlit module handles stateful batching, tracking progress while utilizing vector-free hash deduplication on canonical URLs:

pages/3_Merge_and_Deduplicate_CSVs.py Python 
import pandas as pd
import streamlit as st

def merge_and_clean_datasets(uploaded_files) -> pd.DataFrame:
    # Aggregate distinct session extractions
    dfs = [pd.read_csv(file) for file in uploaded_files]
    merged_df = pd.concat(dfs, ignore_index=True)
    
    initial_rows = len(merged_df)
    
    # Normalize URLs & drop redundant entries
    merged_df['Clean_Link'] = merged_df['Link'].astype(str).str.strip().str.lower()
    deduped_df = merged_df.drop_duplicates(subset=['Clean_Link'], keep='first')
    deduped_df = deduped_df.drop(columns=['Clean_Link'])
    
    st.info(f"Consolidated {initial_rows} records down to {len(deduped_df)} unique entries.")
    return deduped_df

Simultaneously, the REST API service (api.py) exposes a high-throughput endpoint with full OpenAPI contract validation via Pydantic:

api.py Python 
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, HttpUrl
from typing import List
from rss_parser.parser import extract_article_content, generate_llm_summary

app = FastAPI(title="RSS & URL Summarizer API", version="1.0.0")

class SummarizeRequest(BaseModel):
    urls: List[HttpUrl]

class SummaryResult(BaseModel):
    url: str
    title: str
    content_preview: str
    summary: str

@app.post("/summarize", response_model=List[SummaryResult])
async def batch_summarize(payload: SummarizeRequest):
    results = []
    for target_url in payload.urls:
        try:
            parsed = extract_article_content(str(target_url))
            summary_text = generate_llm_summary(parsed["text"])
            results.append(SummaryResult(
                url=str(target_url),
                title=parsed["title"],
                content_preview=parsed["text"][:250] + "...",
                summary=summary_text
            ))
        except Exception as err:
            raise HTTPException(status_code=500, detail=f"Failed to process {target_url}: {str(err)}")
    return results

Container Orchestration: Concurrent Services

Running an interactive dashboard alongside a REST API typically requires two container instances or complex reverse proxies. The suite simplifies deployment using a lightweight entrypoint script (start.sh) inside a single python:3.11-slim container, orchestrating both Uvicorn and Streamlit:

start.sh & Dockerfile Bash / Docker 
#!/bin/bash
# Launch FastAPI backend on port 8000
uvicorn api:app --host 0.0.0.0 --port 8000 &

# Launch Streamlit frontend dashboard on port 8501
streamlit run app.py --server.port 8501 --server.address 0.0.0.0 &

# Wait on any background process termination
wait -n
exit $?

Production Recommendations & Conclusion

By separating high-frequency HTML DOM cleanup from the LLM prompt layer, the RSS & URL Summarizer Suite achieves predictable token expenditure while maintaining high extraction quality.

  • Heuristic Pre-tokenization is Non-Negotiable: Running raw HTML strings through an LLM introduces redundant tags, causing context inflation and 5x to 10x higher API bills.
  • Enforce Response Contracts: Explicit three-tier prompts (TL;DR, 3-5 bullets, categorizing tags) ensure consistent structure across downstream tools like Slack alerts, Notion databases, or CRM feeds.
  • Unified Containerization: Bundling Uvicorn alongside Streamlit using a background process runner minimizes cloud hosting costs for internal productivity tooling.
