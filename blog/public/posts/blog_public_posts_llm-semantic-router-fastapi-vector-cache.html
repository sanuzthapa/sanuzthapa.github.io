The Architectural Dilemma: LLM-Based Routing is Too Slow

In modern generative AI production stacks, incoming user requests vary wildly: customer support questions, SQL query generation, code review requests, or conversational chit-chat. The conventional approach involves sending every inbound prompt to a top-tier general model like GPT-4o with instructions like:

"Classify the following query into [SQL, CodeReview, Support, General] and output only JSON."

This introduces an immediate 800ms to 2,500ms delay and burns prompt tokens before actual work starts. Semantic routers replace this entire inference step by projecting user intents into high-dimensional embedding spaces, computing fast cosine similarities against anchored reference embeddings, and routing requests dynamically.

Architecture & Request Flow

Implementation Details: NumPy Matrix Multiplication

Instead of calling external vector databases on every request, reference utterances for each route are pre-embedded at startup and stored as a normalized 2D tensor. Computing the similarity score reduces to a single vectorized matrix product: 

# router/engine.py
import numpy as np
from pydantic import BaseModel
from sentence_transformers import SentenceTransformer

class RouteMatch(BaseModel):
    route_name: str
    score: float
    target_backend: str

class SemanticRouter:
    def __init__(self, routes: dict[str, list[str]], model_name: str = "BAAI/bge-m3"):
        self.encoder = SentenceTransformer(model_name)
        self.route_names = []
        self.reference_embeddings = []
        
        # Pre-compute and normalize anchor vectors
        for name, utterances in routes.items():
            emb = self.encoder.encode(utterances, normalize_embeddings=True)
            for vec in emb:
                self.route_names.append(name)
                self.reference_embeddings.append(vec)
                
        self.matrix = np.array(self.reference_embeddings)

    def route(self, query: str, threshold: float = 0.72) -> RouteMatch:
        query_vec = self.encoder.encode([query], normalize_embeddings=True)[0]
        # In-memory dot product: (N, D) @ (D,) -> (N,)
        similarities = self.matrix @ query_vec
        best_idx = int(np.argmax(similarities))
        best_score = float(similarities[best_idx])
        
        if best_score >= threshold:
            return RouteMatch(
                route_name=self.route_names[best_idx],
                score=best_score,
                target_backend=f"srv-{self.route_names[best_idx].lower()}"
            )
        return RouteMatch(route_name="fallback", score=best_score, target_backend="srv-general-llm")

Production Deployment Tips

  • Normalize Vectors at Ingestion: Always normalize your reference embeddings so that cosine similarity reduces to a dot product ($A \cdot B$), avoiding expensive square root operations at runtime.
  • Dynamic Thresholding: High-risk workflows (such as financial transactions or production code execution) should enforce high confidence thresholds ($\ge 0.82$), gracefully cascading ambiguous prompts to human escalation or larger frontier models.
  • Zero Cold Starts: Serializing your anchor matrix as a compressed .npz file allows instantaneous FastAPI startup in Kubernetes clusters without recalculating embeddings.
